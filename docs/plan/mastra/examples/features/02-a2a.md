# A2A (Agent-to-Agent) — mdeai

**Official:** [A2A](https://mastra.ai/docs/agents/a2a) · [a2a-protocol.org](https://a2a-protocol.org/latest/)

Expose Mastra agents as **remote** endpoints (agent card + JSON-RPC) or consume third-party agents via `A2AAgent` on a supervisor.

---

## mdeai today vs target

| Item | Today | Target |
|------|-------|--------|
| `A2AAgent` subagents | **None** | Partner weather / ticketing vendor |
| Mastra Server A2A routes | `:4111` dev only | **Not** prod traffic — product stays Pattern 1 |
| Signed agent cards | — | Patricia-enforced trust before delegate |

Phase 1 **does not** route Camila through `:4111/api/a2a/*`. CopilotKit owns the browser edge.

| Capability | mdeai use case |

## Journey — partner delegate (Phase 3 sketch)

1. User message on `/chat` → CopilotKit → `conciergeAgent`.
2. Supervisor lists `remoteExperiencesAgent` (`A2AAgent` with signed card).
3. Remote agent runs task `task-abc`; stream artifacts back.
4. Concierge summarizes + renders **local** map card from our `search-events` tool if needed.

**CopilotKit:** No change to `runtimeUrl` — A2A is **inside** the Mastra graph, not a second browser runtime.
