## 30. API structure

| Route | Method | Purpose | Runtime |
|---|---|---|---|
| `/api/copilotkit` | POST | CopilotRuntime + Mastra agents | Fluid Compute (Node 24) |
| `/api/approval-commit` | POST | Wraps `decide_approval()` RPC | Fluid Compute |
| `/api/leads` | POST | Lead capture (anon allowed) | Fluid Compute |
| `/api/places/autocomplete` | GET | Cached Places autocomplete | Fluid Compute |
| `/api/healthz` | GET | Health check | Fluid Compute |

All Supabase reads/writes from frontend use `@supabase/supabase-js` directly (RLS enforces auth).

## 31. Recommended agents

| Agent | Phase | Tools |
|---|---|---|
| `pingAgent` | W1 | none |
| `hostEventAgent` | W3 | `set_event_basics`, `set_venue`, `add_ticket_tier`, `preview_and_publish` |
| `rentalAgent` | W5 | `search_rentals`, `render_rental_card` |
| `eventAgent` | W6 | `search_events`, `render_event_card` |
| `conciergeAgent` | W6 | `search_grounded_places`, `render_grounded_place_card` — note: `routerAgent` is a separate **dispatching agent**, not a tool; concierge does not embed it |
| `routerAgent` | W6 | intent classification — dispatches to specialist agents (replaces legacy `useIntentRouter`) |

## 32. Recommended workflows

Mastra workflows:

| Workflow | Steps | Phase |
|---|---|---|
| `create-event` | parse → venue-lookup → tier-suggest → preview → approve → commit | W3 |
| `discover-rentals` | filter → embedding-search → rank → return cards | W5 |
| `grounded-search` | query → grounding-lite → places-enrich → cache → return cards | W6 |
| `event-publish-decision` | preview → user-decision → on-approve commit / on-reject log | W4 |

## 34. Zod schema strategy

**Single source:** `packages/types/src/`. Both `src/` (frontend) and `mdeapp/src/mastra/tools/` import from here.

```ts
// packages/types/src/event-draft.ts
import { z } from "zod";

export const TicketTier = z.object({
  name: z.string().min(1).max(60),
  priceCop: z.number().int().positive(),
});

export const EventDraftState = z.object({
  title: z.string().default(""),
  date: z.string().nullable().default(null),
  venueName: z.string().default(""),
  venuePlaceId: z.string().nullable().default(null),
  description: z.string().default(""),
  ticketTiers: z.array(TicketTier).default([]),
});

export type EventDraftState = z.infer<typeof EventDraftState>;
```

**Eliminates FP-1 audit finding** (kebab/camel drift between Mastra tool + frontend renderer).

## 35. Type safety strategy

- **Strict TypeScript** (`strict: true`)
- **No `any`** — use `unknown` and narrow
- **Component props in explicit `interface`** — not inline
- **All Supabase reads use generated types** from `supabase gen types typescript`
- **All Mastra tool outputs Zod-validated** at edge
- **Vercel `vercel.ts`** for typed deployment config (replaces `vercel.json`)
