# 1. Executive Summary

## What Paperclip AI Is

[Paperclip AI Docs](https://docs.paperclip.ing/?utm_source=chatgpt.com#/)  
[Paperclip GitHub](https://github.com/paperclipai/paperclip?utm_source=chatgpt.com)

Paperclip is an AI orchestration and governance framework designed to manage:

- AI agents
    
- projects
    
- workflows
    
- execution policies
    
- budgets
    
- approvals
    
- tasks
    
- organizational structures
    

It acts like:

> “an operating system for AI companies”

In practice:

- OpenClaw executes actions
    
- Hermes thinks/reasons
    
- Postiz distributes content
    
- Paperclip supervises and governs all of them
    

---

## What Problem It Solves

Without Paperclip:

- AI agents can overspend
    
- spam users
    
- trigger unsafe workflows
    
- hallucinate actions
    
- create operational chaos
    

Paperclip solves:

- budget control
    
- approval gates
    
- execution permissions
    
- task routing
    
- audit trails
    
- organizational management
    

---

## Does It Fit mdeai?

## YES — but NOT first.

Best use timing:

- AFTER rentals MVP works
    
- AFTER WhatsApp workflows exist
    
- AFTER OpenClaw/Hermes are operational
    

Paperclip is:

- governance infrastructure
    
- not customer-facing revenue infrastructure
    

---

## Recommendation

|Stage|Recommendation|
|---|---|
|Rentals MVP|❌ Do not use yet|
|Lead CRM + WhatsApp|⚠ Minimal use only|
|Multi-agent automation|✅ Strong fit|
|High-scale operations|✅ Excellent fit|

# 5. Integration Architecture

## Recommended Stack

```text
Supabase
= source of truth
(users, listings, leads, payments, audit logs)

Hermes
= intelligence layer
(ranking, reasoning, memory, matching)

OpenClaw
= execution layer
(WhatsApp, scraping, browser actions, CRM)

Postiz
= growth layer
(social scheduling, campaigns, listing promotion)

Paperclip
= governance layer
(approvals, budgets, tasks, audit)
```

---

## Data Flow

```text
User message →
OpenClaw →
Hermes reasoning →
Supabase write →
Paperclip policy validation →
Execution →
Audit log →
Postiz promotion
```

---

## Where Approvals Should Happen

|Workflow|Approval?|
|---|---|
|High-value payments|YES|
|Refunds|YES|
|Lease summaries|YES|
|Bulk WhatsApp outreach|YES|
|Auto-post social campaigns|Usually NO|
|Showing scheduling|Usually NO|

---

## What Should NOT Be Automated

Avoid fully autonomous:

- refunds
    
- legal advice
    
- contract signing
    
- eviction decisions
    
- discrimination-sensitive screening
    
- financial commitments
