# Plan — SAN-118 / EVT-014 · Host events list page (`/host/events`)

## Context

Roberto creates events via the `/host/event/new` wizard, but **there is no page where he can see them afterward** — `mdeapp/src/app/host/events/page.tsx` does not exist. The use case ("Roberto sees *Medellín Tech Meetup* + draft events on `/host/events`") requires a read-only list that distinguishes draft vs published.

This is a **basic screen**: render the host's own events as a card grid with a status chip + empty-state CTA. No editing, no delete, no pagination, no filters wired to UI beyond what's trivial. It is **unblocked** today — the audit that called it "blocked / 55/100" was wrong:

- Its `blockedBy` SAN-117 (EventCard) is **Done** (PR #14, 2026-05-30); the component exists at `src/components/copilot/event-card.tsx`.
- Its other `blockedBy` SAN-97 (SYS-003 hero photos) is open but **cosmetic + optional** — the card renders an "Event photo" placeholder when `imageUrl` is absent.
- RLS is ready: policy `events_organizer_select_own` (`organizer_id = auth.uid()`, in `supabase/migrations/20260517045810_evt001_events_rls_alignment.sql`) lets the host read their own draft + unpublished rows with the normal authed client — **no service-role**.

## Key decisions

1. **Thin `HostEventCard`** reusing the visual tokens of `EventCard` but with a **status chip** (Draft / Pending / Approved / Published) instead of "Buy tickets". Composition, not a fork of EventCard's logic.
2. **Status-aware CTA, bounded by routes that actually exist.** Only `/host/event/new` exists — there is **no edit, publish, or draft-preview route**. So: `published` + has `slug` → **"View public event"** link → `/events/[slug]`; every other status → chip only, **no action link** (no dead links, no misleading "edit" that starts a new event). Do NOT invent "Continue setup"/"Publish" CTAs.
3. **Real DB column is `organizer_id`, not `host_id`.** The spec file has `host_id` — correct it as part of this work.
4. **Auth: defense-in-depth.** `/host` is already a protected middleware prefix, but the page still does `const { user } = await getServerUser(); if (!user) redirect("/login?next=/host/events")` before querying (matches the `!user` branch in `trips/page.tsx`).
5. **Price display:** the mapper **preserves null** (`priceMin: row.ticket_price_min ?? null`, type `number | null`) — never coerce to 0. Card: `priceMin == null ? "Price TBD" : "From $" + priceMin.toLocaleString()`. (null ≠ free.) This is why `HostEventCard` has its own props type, not `EventCardProps` whose `pricePerTicket` is a required `number`.
6. **Header:** primary **"Create event"** button → `/host/event/new` (real route) + back link to `/`. No "Back to dashboard" — there is no `/host` dashboard route.
