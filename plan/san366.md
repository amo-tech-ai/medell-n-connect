 Plan — Host authed Playwright e2e fixture (SAN-366 follow-up)

 Context

 The SAN-366 / SAN-118 work could only prove the logged-out redirect +
 empty state for /host/events — there was no authenticated Playwright
 fixture, so the populated host grid (a published event showing as a card)
 was only covered by component tests. This task adds the authed fixture so
 the host list can be proven end-to-end with a real Supabase session.

 Key discovery: the repo already has the auth pattern inline in
 e2e/screens/SCREEN-013-itinerary.spec.ts (injectQaLandlordSession +
 loadEnvLocalForE2E, L67–135): admin generateLink(magiclink) → verifyOtp →
 inject the sb-<ref>-auth-token cookie for test user qa-landlord@mdeai.co.
 So this is extract + reuse, not build-from-scratch.

 This is integration e2e (needs a real Supabase connection +
 SUPABASE_SERVICE_ROLE_KEY + the qa-landlord user). It runs in the
 Playwright suite (test:e2e:*), not in floor/Vitest CI. It does not depend
 on PR #64's code — it seeds organizer_id directly, so it independently
 proves the /host/events organizer filtering + RLS.

 Approach

 1. Extract the auth helper → e2e/helpers/auth.ts:
   - loadEnvLocalForE2E() (moved verbatim from SCREEN-013).
   - getTestSession(email) → returns the Supabase session (so callers get
 session.user.id for seeding).
   - injectSession(page, session) → sets the sb-<ref>-auth-token cookie
 (the body of injectQaLandlordSession).
   - signInAs(page, email) → convenience: getTestSession + injectSession,
 returns session.
   - Default email constant QA_HOST_EMAIL = "qa-landlord@mdeai.co".
   - (Optional cleanup, recommended): refactor SCREEN-013 to call the
 shared helper to kill the duplication. Keep behavior identical.)
 2. Seed helper → e2e/helpers/seed-event.ts (uses the service-role admin
 client, env names only — never log values):
   - seedPublishedEvent(organizerId, { slug })  → inserts a public.events
 row mirroring the wizard insert (reuse buildEventInsert from
 supabase/functions/approval-commit/build-event-insert.ts — same cross-dir
 import already used by src/__tests__/build-event-insert.test.ts),
 status:'published', unique slug. Ensures a profiles row exists for
 organizerId first (FK events.organizer_id → profiles.id); returns { id,
 slug, name }.
   - deleteEvent(id) → cleanup.
 3. New spec → e2e/screens/SCREEN-016c-host-events-authed.spec.ts (serial;
 desktop + mobile via existing viewport consts):
   - beforeAll: session = await getTestSession(QA_HOST_EMAIL); seeded =
 await seedPublishedEvent(session.user.id, {slug: "qa-host-events-<n>"}).
   - afterAll: deleteEvent(seeded.id) (always, even on failure).
   - desktop test: injectSession(page, session) → goto("/host/events") →
 assert host-events-list visible, a host-event-card with the Published chip
 + host-event-view-link → /events/<seeded.slug>, and the empty-state
 (host-events-empty) is absent; assertConsoleClean;
 captureScreenEvidence(SCREEN-016c, "desktop-host-events-populated.png").
   - mobile test: same assertions at MOBILE_VIEWPORT + screenshot.
   - Reuse watchCriticalConsoleErrors / assertConsoleClean /
 captureScreenEvidence from e2e/helpers/screen-evidence.ts.
 4. Script → add "test:e2e:host-events": "playwright test
 e2e/screens/SCREEN-016c-host-events-authed.spec.ts --project=chromium
 --workers=1" to package.json.

 Files

 - Create: e2e/helpers/auth.ts, e2e/helpers/seed-event.ts,
 e2e/screens/SCREEN-016c-host-events-authed.spec.ts
 - Modify: package.json (script); (optional)
 e2e/screens/SCREEN-013-itinerary.spec.ts (use the shared helper)
 - Reuse: screen-evidence.ts (viewports, console, screenshot), the
 SCREEN-013 session pattern, build-event-insert.ts, data-testids already on
 the page (host-events-list, host-event-card, host-event-status,
 host-event-view-link, host-events-empty).

 Constraints / caveats

 - Secrets: read SUPABASE_SERVICE_ROLE_KEY / NEXT_PUBLIC_SUPABASE_* from
 env by name only; never print values. Helper lives in e2e/ (not src/**),
 so the no-service-role-in-src hook is satisfied.
 - Shared prod Supabase (zkwcbyxiwklihegjhuql is reused): the seed writes a
 real row → unique slug + guaranteed afterAll cleanup to avoid pollution;
 the seeded event is published, so it's briefly publicly visible during the
 run.
 - Not in floor: this spec won't run in Vitest CI; it's a Playwright
 integration test requiring env + network. Document the run command.
